## 调研范围

- **第一轮**: 英文网站 + Steam + GitHub — 桌面 AI 伴侣全景扫描
- **第二轮**: 中文网络 + 36氪/QbitAI/界面/澎湃 — 国内抖音/短视频生态
- **验证方法**: 每轮提取 25 条声明, 3 个独立 agent 交叉验证 (3-0 = 通过, 2-1 = 存疑, 0-3/1-2 = 驳回)

## 2. waifu-agent vs 竞品对比

### 2.1 优势

## 3. 关键趋势

### 3.1 Steam 桌宠价格战已开始

N.E.K.O. 免费 (MIT 开源) → AI Desktop Pet $12.99 → Ipet ¥15。**一次性买断, 无订阅模式。** 价格向 0 收敛, 靠数量盈利难。

### 3.2 Live2D 赛道在收窄, 不是变卷

- Alive 放弃 Live2D → 闭源
- Cloe 不用 Live2D
- OpenPet 用 spritesheet
- AIFE 停留在 Cubism v3
- **用 Cubism 4 做桌面应用的只剩 waifu-agent**

### 3.3 "本地推理" 成 Steam 竞品标配

AI Desktop Pet 的核心卖点是 "no API keys needed" + 本地 GPU 推理。N.E.K.O. 也支持多后端但更灵活。Open-LLM-VTuber 完全离线。

### 3.4 开源项目方向分化, 无正面冲突

- VTubing/直播: Open-LLM-VTuber, Persona Engine
- 游戏 AI 陪玩: 逗逗AI, 桌崽AI, AIRI
- 轻量桌宠: AIFE, OpenPet
- 工作 Agent (无角色): 有道龙虾
- **Agent 前端 (有角色): waifu-agent 独占**

## 4. 差异化空间

### 4.1 已验证的机会

1. **"Agent 的脸" 定位无人占领** — 有道龙虾验证了"工作 Agent" 需求, 但它没角色界面。交叉两者 = 空白。
2. **许可/变现基础设施是护城河** — 所有竞品 (包括 Steam 付费产品) 都没有设备绑定/激活码系统。
3. **Tauri 2 跨平台未启用** — 大部分竞品 Windows-only, Tauri 2 可编译 macOS 但 waifu 还没用。

### 4.2 不该拼的方向

- **拼角色数量** → Ipet 100+, 一人团队不可能
- **拼 VLM 视觉感知** → 逗逗AI 自研模型, 字节养着
- **拼 Steam Workshop 生态** → N.E.K.O. 先发优势 + MIT 开源社区
- **拼本地推理** → 打包 Qwen-7B 增加 4GB 安装包, 且与 waifu 轻量定位冲突

### 4.3 待验证的假设

- "打工人搭子 + 角色界面" 是否能融合 (有道龙虾 40% 用户认为"半成品玩具")
- 抖音 AI 桌宠脱口秀是内容趋势还是产品机会
- Steam 桌宠的真实留存数据 (只有桌崽AI 报过, 被驳斥)

## 7. 逐维度差距分析 (waifu-agent vs 各维度市场最佳)

以下按维度逐一比较 waifu-agent (v0.8) 与当前该维度的**最强竞品**。

### 7.1 渲染管线 (Cubism 版本)

| | waifu-agent | 最佳: Open-LLM-VTuber |
|--|:--|:--|
| Live2D SDK | **Cubism 4** (Pixi.js 7) | **Cubism 5** (v1.2.0 升级) |
| 其他格式 | 仅 Live2D | VRM, MMD (via Three.js) |
| 前景 | Cubism 4 在桌面领域已是最高版本之一, 5 仅有 Open-LLM-VTuber 在用 | |

**差距**: 中等。Cubism 4→5 的升级主要是性能优化, 不影响功能。但缺 VRM/MMD 支持是硬伤——意味着用户不可能用 VRChat 模型。

---

### 7.2 角色/模型数量

| | waifu-agent | 最佳: Ipet |
|--|:--|:--|
| 可选角色 | **2 个模型, 7 套预设** (6 套共用同一 Haru Greeter) | **100+** 个动漫角色 |
| 用户自定义 | 不支持, 模型路径硬编码在 persona.config.ts | 内置选择器 |
| 模型热加载 | 切换 persona 重载, 无过渡动画 | 即时切换 |

**差距**: 巨大。这是 waifu-agent 最明显的短板。用户看一眼就走了——"就两个角色？"

---

### 7.3 桌面框架轻量化

| | waifu-agent | 最佳: waifu-agent |
|--|:--|:--|
| 框架 | **Tauri 2** (Rust + WebView2) | Electron (Open-LLM-VTuber, Cloe) |
| 运行时体积 | ~5MB | ~150MB+ (Electron + Chromium) |
| 内存占用 | 低 | 高 |

**差距**: waifu **领先**。这是 Tauri 2 的天然优势。

---

### 7.4 口型同步精度

| | waifu-agent | 最佳: waifu-agent (推测) |
|--|:--|:--|
| 算法 | 42 韵母→5 元音 (a/i/u/e/o), 逐字映射, 正弦波调幅+噪声 | 多数竞品用简单"张嘴闭嘴", Open-LLM-VTuber 有唇形同步但精度不详 |
| 验证 | 代码内有逐帧读回验证 (ParamI/U/E/O ~90% 保真) | 无数据 |

**差距**: waifu **可能领先**。但竞品唇形同步数据缺失, 无法严格比较。

---

### 7.5 记忆/人格系统

| | waifu-agent | 最佳: N.E.K.O. |
|--|:--|:--|
| 维度 | SOUL.md (人设) + USER.md (用户描述) + MEMORY.md (AI 按规则写入) | **5 维**: facts (事实), reflection (反思), persona (人格), 独立记忆服务器 |
| 自动蒸馏 | distill_memory → 每日提炼念头 | 结构化的 memory_server.py 独立进程 |
| 用户可编辑性 | USER.md 手动编辑, SOUL.md 手动编辑 | 通过 UI 管理 |

**差距**: 中等偏大。N.E.K.O. 的 5 维记忆系统更结构化、可扩展。waifu 的三层文件方案够用但粗糙。

---

### 7.6 Agent 能力 — "做事而非聊天"

| | waifu-agent | 最佳: 有道龙虾 (LobsterAI) |
|--|:--|:--|
| 工具调用 | 无。v0.8 relay 模式把 Agent 外包给外部 | **29 个内置技能**: PPT/PDF 生成, 浏览器自动化, 视频生成, 文档分析 |
| Agent 可视化 | 有 (Live2D 角色 + 表情 + 语音) | **无角色界面**, 纯命令行/系统托盘 |
| 定位 | "Agent 的脸" | "7x24 数字员工" |

**差距**: 结构性互补。有道龙虾是 Agent 但没脸, waifu 有脸但不是 Agent。**如果 waifu 内置几个简单工具 (文件操作/系统信息/剪贴板), 就和有道龙虾形成差异化——既有 Agent 能力又有角色界面。**

---

### 7.7 视觉感知

| | waifu-agent | 最佳: 逗逗AI / Open-LLM-VTuber |
|--|:--|:--|
| 桌面画面感知 | **无** | 逗逗AI: VLM 实时游戏画面分析, 自研模型 (LynkSoul 超 GPT-4o) |
| 摄像头 | **无** | Open-LLM-VTuber: 摄像头+录屏接入 LLM |
| 截图 | **无** | Open-LLM-VTuber: 截图送 AI 分析 |

**差距**: 巨大。但这是**字节级投入**, 一个人不可能拼。不宜追击。

---

### 7.8 分发渠道

| | waifu-agent | 最佳: N.E.K.O. |
|--|:--|:--|
| 渠道 | **手动下载 MSI** | **Steam 免费上架** + Steam Workshop |
| 社区内容 | 无 | 插件 SDK + Workshop UGC |
| 版本更新 | 手动覆盖安装 | Steam 自动更新 |

**差距**: 巨大。Steam 是天然流量池, waifu 目前完全没有。上架 Steam 是技术可行的 (Tauri 2 可以打包), 只是没做。

---

### 7.9 桌宠模式 (窗口穿透/click-through)

| | waifu-agent | 最佳: Open-LLM-VTuber |
|--|:--|:--|
| 窗口行为 | 置顶悬浮窗 (装饰: false, 可拖拽) | **click-through 穿透模式** (v1.2.0) — 角色在桌面上但不阻挡鼠标操作 |
| 交互方式 | 必须点中窗口才能拖拽角色 | 角色在桌面"上"但鼠标穿过直达下方应用 |

**差距**: 中等。Click-through 是"桌宠感"的关键。waifu 目前做不到——窗口区域会挡住鼠标。

---

### 7.10 本地推理 (离线可用)

| | waifu-agent | 最佳: AI Desktop Pet |
|--|:--|:--|
| 推理方式 | **必须连外部 API** (DeepSeek 等) | **100% 本地**: 捆绑 Qwen2.5-7B-Instruct + CUDA/Vulkan GPU 推理 |
| 隐私 | API key + 云端 | 全本地, 无数据外传 |
| 安装体积 | ~50MB | **~4GB** (大模型) |

**差距**: 存在但不该追。waifu 的轻量 (50MB) 是优势, 捆绑 4GB 模型会毁掉这个优势。可考虑 Ollama 可选后端但不捆绑。

---

### 7.11 TTS 语音合成

| | waifu-agent | 最佳: Open-LLM-VTuber |
|--|:--|:--|
| 引擎 | edge-tts → Azure Xiaoxiao (中文优秀) + Web Speech API 兜底 | **多引擎**: GPT-SoVITS, CosyVoice, Edge TTS, 可定制音色 |
| 音色数量 | **1 种** (Xiaoxiao) | 多种可选 |
| 流式播放 | 逐句 TTS (句子分割→合成→播放), 非实时 | 配置驱动 |

**差距**: 中等。Xiaoxiao 音质好但单一。多音色在"角色切换"场景有意义。

| 语言 | 中文/自动检测 | 多语言 |

**差距**: 小。waifu 的 STT 方案够用, 多引擎是锦上添花。

## 8. 差距优先级矩阵

按 **用户感知度** × **实现难度** 排列:

| 优先级 | 差距 | 用户感知 | 难度 | 动作 |
|:--:|------|:--:|:--:|------|
| 🔴 P0 | 只有 2 个模型 | 极高 | 中 | 模型导入系统 (不改代码加载新模型) |

**核心矛盾**: waifu-agent 在**工程技术深度**(Cubism4 管线/口型算法/Tauri2 轻量)上领先或持平, 但在**用户看得见的地方**(角色数量/分发渠道/点击穿透)落后。

**产品化的最短路径**: 模型导入系统 → Steam 上架 → 角色多样性 → 记忆系统升级。
