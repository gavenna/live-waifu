# 工程体系演进

> 2026-07-05 · 对标 Claude Code 2026 前沿实践，评估当前工程体系差距与演进路线。

## 当前状态

### 架构

```
1 Agent (flow-debugger) + 6 Skill (backend/frontend/cubism/prompt/review/deploy)
4 层 Harness Hook (PreToolUse ×1 + PostToolUse ×2 + Stop ×2)
CLAUDE.md (~100 行) + rules/ (git.md + pitfalls.md)
```

### 已做对的

| 实践 | 行业共识 |
|------|---------|
| Agent/Skill 正交划分（隔离 vs 知识） | Anthropic 官方模型 |
| Hook 机械执行 > 指令依赖 | 指令遵从率 ~20%，Hook 执行率 100% |
| pitfalls.md 踩坑登记簿 | Anthropic：Skill 最有价值的部分是 Gotchas |
| 10 agent → 1 agent + 6 skill | 官方警告：避免铁路化 Agent |
| CLAUDE.md 从 395 行砍到 100 行 | Lago 团队：829 行 → 275 行，按需加载 |

## 2026 前沿对标

### Skill 文件夹化（🔴 优先）

**现状**：6 个 Skill 全部是单文件 `SKILL.md`。

**前沿**：Skill 是文件夹，包含可执行脚本和参考资料。

```
.claude/skills/review/
├── SKILL.md              # 检查清单（入口）
├── scripts/              # 可执行验证脚本
│   ├── check-stickers.sh
│   └── check-timing.sh
└── references/           # 长文档、基线标准
    └── quality-baseline.md
```

Agent 不只是读指令，还能**执行脚本拿到真实数据**再判断。

参考：[Lessons from building Claude Code: How we use skills](https://claude.com/blog/lessons-from-building-claude-code-how-we-use-skills)

### 产品验证 Skill（🔴 优先，ROI 最高）

**现状**：`/review` 手动触发，检查维度手动执行。

**前沿**：做成 Stop hook 自动跑。Anthropic 原话——验证 Skill "对输出质量提升最可度量，值得让一个工程师花一整周打磨"。

自动检查项：
- 贴图是否生成（不只看 API 不报错，读实际文件）
- TTS 清洗是否生效（构造含 `[tag]` 的测试句）
- 口型同步偏差（日志时间戳对比）
- 状态机时序（thinking → speaking → idle 间隔是否正常）

参考：[Steering Claude Code: skills, hooks, subagents and more](https://claude.com/ko/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)

### 对抗审查（🔴 优先）

**现状**：所有代码主会话一人写，无人 challenge。

**前沿**：

```
写完代码 →
  spawn skeptic agent（只读，挑逻辑漏洞）
  spawn simplifier agent（只读，找重复/过度设计）
  两个都没问题 → 提交
```

关键改动（auth、settings、数据持久化）走这个流程，能抓出自己看不出的问题。

参考：[Fable Harness](https://github.com/Miguok/fable-harness) — OODA + multi-party adversarial review

### 模型路由（🟡）

**现状**：全部用默认模型。

**前沿**：按任务选模型。

| 任务 | 模型 | 原因 |
|------|------|------|
| 架构设计、安全审查 | Opus | 推理能力强 |
| 写代码、重构、debug | Sonnet | 速度快，编码质量高 |
| 文档生成、批量文件操作 | Haiku | 成本低，吞吐高 |

### PreCompact Hook（🟡）

**现状**：上下文压缩时无保护。

**前沿**：压缩前通过 Hook 保存关键上下文（当前任务目标、未完成事项），防止目标漂移。

### Worktree 隔离（🟡）

**现状**：flow-debugger 在主工作区排查。

**前沿**：agent 启用 `isolation: worktree`，每次排查在隔离的 git worktree 里，不干扰主工作区。

### Skill 按需 Hook（⚪）

**现状**：Hook 全局生效。

**前沿**：部分 Hook 只在调用特定 Skill 时激活（如 `/careful` 临时加拦截危险操作）。

参考：[Claude Code 四大定制机制完全指南](https://developer.aliyun.com/article/1745131)

### 动态 Workflow（⚪）

**现状**：所有任务串行。

**前沿**：大规模重构/审计时用 Workflow 编排多 agent 并行（fan-out → verify → synthesize）。

参考：[A harness for every task: dynamic workflows in Claude Code](https://claude.com/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code)

## 演进路线

```
Phase 1（本次）: Skill 文件夹化 + 产品验证 Skill
Phase 2:         对抗审查 agent + 模型路由
Phase 3:         PreCompact Hook + Worktree 隔离
Phase 4:         Skill 按需 Hook + 动态 Workflow（按需）
```
