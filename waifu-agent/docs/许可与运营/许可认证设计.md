# 许可验证系统 — 终版设计

> 最后更新: 2026-05-29
> 状态: 后端已完成 ✅，客户端已完成 ✅ (部署 Vercel + Neon)

---

## 1. 概述

**支付端**：爱发电赞助 → 管理员生成激活码 → 私信发给用户
**验证端**：用户输入激活码 → waifu-auth 验证 → 绑定设备 → 本地 token 缓存 → 离线可用

不需要手机号、不需要密码、不需要短信验证码。

## 2. 完整闭环

```
你 (管理员)                  用户                       waifu-auth
│                           │                           │
├─ 爱发电收到赞助通知         │                           │
├─ gen-key.ts --tier pro    │                           │
├─ 私信发激活码  ──────────→  │                           │
│                           ├─ 打开 App                 │
│                           ├─ 输入激活码  ────────────→  │
│                           │                           ├─ 校验激活码 (未用/未过期)
│                           │                           ├─ 创建/更新用户 (tier 继承)
│                           │                           ├─ 绑定机器码 (≤ device_limit)
│                           │                           ├─ 签发 JWT (access + refresh)
│                           │   ←── 返回 token ────────  │
│                           ├─ 缓存 token 到本地         │
│                           ├─ 进入主界面               │
│                           │                           │
│  (30 天内)                 ├─ 启动 App                 │
│                           ├─ 本地 token 有效 → 直接进  │
│                           ├─ access 过期 → refresh     │
│                           │   ←── 新的 access_token ──  │
│                           │                           │
│  (30 天后，token 全过期)    │                           │
│                           ├─ 回退到激活码输入页        │
│                           ├─ 赞助续期 → 新激活码 → 激活 │
│                           │                           │
│  用户换电脑                │                           │
│                           ├─ 输入激活码                │
│                           │   ←── 超过设备数 ────────  │
│                           ├─ 找管理员解绑旧设备        │
│                           ├─ 重新激活                  │
```

## 5. 服务端 API

Base URL: `https://waifu-agent.vercel.app/api`

### 5.1 用户端

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth-activate` | 激活码 + 机器码 → 创建用户 + 绑定设备 + 签发 JWT（已绑定设备自动 re-auth） |
| POST | `/api/auth-refresh` | 刷新 access_token + refresh_token（滚动更新） |
| POST | `/api/auth-logout` | 登出 (撤销 refresh_token) |
| GET | `/api/auth-verify` | 验证 token + 用户状态 + 设备绑定（封禁/解绑即时生效） |
| POST | `/api/devices` | 绑定设备（POST machine_code） |
| GET | `/api/devices` | 查看已绑定设备 / 检查某设备是否绑定（?machine_code=） |
| DELETE | `/api/devices` | 解绑指定设备（?id=） |

### 5.2 管理端

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/admin-login` | 管理员登录 |
| POST | `/api/admin-reg-keys` | 生成激活码 |
| GET | `/api/admin-reg-keys` | 激活码列表 |
| DELETE | `/api/admin-reg-keys` | 删除激活码 |
| GET | `/api/admin-users` | 用户列表 / 搜索 |
| GET | `/api/admin-users/:id` | 用户详情 + 设备 |
| POST | `/api/admin-users/:id/ban` | 封禁/解封用户 |
| POST | `/api/admin-users/:id/unbind-all` | 解绑所有设备 + 恢复激活码 + 删除用户 |
| DELETE | `/api/admin-users/:id` | 删除用户 |
| GET | `/api/admin-stats` | 统计概览 |
| POST | `/api/admin-change-password` | 修改管理员密码 |

### 5.4 核心请求/响应

```
POST /api/auth/activate
Body: { activation_code: "WA-PRO-ABCD", machine_code: "abc123...", device_name: "Gaven-PC" }
Response: {
  code: 0,
  data: {
    access_token: "eyJ...",
    refresh_token: "eyJ...",
    expires_in: 7200,
    tier: "pro",
    device_limit: 3,
    device_count: 1
  }
}

POST /api/auth/refresh
Body: { refresh_token: "eyJ..." }
Response: {
  code: 0,
  data: { access_token: "eyJ...", expires_in: 7200 }
}
```

## 6. 数据库

```sql
-- 激活码表
CREATE TABLE reg_keys (
    id           BIGSERIAL PRIMARY KEY,
    key_code     VARCHAR(20) UNIQUE NOT NULL,       -- WA-PRO-ABCD
    tier         VARCHAR(10) NOT NULL DEFAULT 'trial',  -- trial/pro/dev
    device_limit INT NOT NULL DEFAULT 1,
    status       SMALLINT DEFAULT 1,                -- 1=未用, 2=已用, 3=过期
    expires_at   TIMESTAMPTZ NOT NULL,              -- 有效期
    used_by      BIGINT REFERENCES users(id),
    used_at      TIMESTAMPTZ,
    created_by   BIGINT REFERENCES admins(id),
    created_at   TIMESTAMPTZ DEFAULT NOW()
);

-- 用户表 (无手机号, 无密码)
CREATE TABLE users (
    id           BIGSERIAL PRIMARY KEY,
    tier         VARCHAR(10) NOT NULL DEFAULT 'trial',
    device_limit INT NOT NULL DEFAULT 1,
    status       SMALLINT DEFAULT 1,                -- 1=正常, 2=封禁
    created_at   TIMESTAMPTZ DEFAULT NOW(),
    updated_at   TIMESTAMPTZ DEFAULT NOW()
);

-- 设备绑定表 (不变)
CREATE TABLE devices (
    id           BIGSERIAL PRIMARY KEY,
    user_id      BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    machine_code VARCHAR(64) UNIQUE NOT NULL,
    device_name  VARCHAR(100) DEFAULT '',
    last_seen    TIMESTAMPTZ DEFAULT NOW(),
    created_at   TIMESTAMPTZ DEFAULT NOW()
);

-- refresh_token 表 (不变)
CREATE TABLE refresh_tokens (
    id         BIGSERIAL PRIMARY KEY,
    user_id    BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    token_hash VARCHAR(64) UNIQUE NOT NULL,
    expires_at TIMESTAMPTZ NOT NULL,
    revoked    BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 管理员表 (不变)
CREATE TABLE admins (
    id         BIGSERIAL PRIMARY KEY,
    username   VARCHAR(50) UNIQUE NOT NULL,
    password   VARCHAR(128) NOT NULL,
    role       VARCHAR(20) DEFAULT 'admin',
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

不再需要 `sms_codes` 表。

## 7. 安全设计

### 7.1 Token 策略

```
access_token:   JWT, 2h 过期
refresh_token:  随机字符串, 30d 过期, 滚动更新 (每次 refresh 换新)
```

### 7.2 机器码

```
machine_code = SHA256(motherboard + os_install_id + machine_guid)
```

Rust 侧 `sysinfo` crate 采集，前端不可见。

### 7.3 限流

| 接口 | 限制 |
|------|------|
| 激活 | 5次/IP/小时 |
| refresh | 正常调用不限 |
| 通用 | 100次/IP/分钟 |

### 7.4 激活码安全

- 激活码 SHA256 哈希存储（`key_code` 存明文用于展示，`key_hash` 单独列可用于查库索引）
- 一次使用，激活后立即标记为已用
- 过期自动失效（`expires_at`）
- 管理员可批量生成，每个码独立追踪

## 8. 客户端实现要点 (Phase 2)

### AuthPanel.tsx

- 简单遮罩，半透明暗色背景
- 居中卡片：Logo + 输入框 + 激活按钮 + "获取激活码"链接
- 无模式切换，无注册/登录/忘记密码
- 激活中：按钮 loading 动画
- 激活失败：红色提示文字
- 激活成功：淡出遮罩，进入主界面

### Rust auth.rs

```
职责:
  - 机器码采集 (sysinfo)
  - token 缓存管理 (~/.waifu-agent/license.json)
  - 自动 refresh
  - 离线模式判断

流程:
  app 启动 → 读 license.json
    ├─ token 有效 (access_token 未过期) → 直接放行
    ├─ access_token 过期, refresh_token 有效 → refresh → 更新缓存 → 放行
    └─ 全过期 → 通知前端显示激活页
```
