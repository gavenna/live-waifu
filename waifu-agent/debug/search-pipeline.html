🔍 断点定位

阻塞第⑥层

A. Python GBK 编码崩溃

Windows stdout 默认 GBK，Bing 爬回的 HTML 含 \xa0 字符（non-breaking space），print() 时 UnicodeEncodeError 导致整个脚本退出。今天 3 次搜索中 2 次因此失败。

影响：阻断整个搜索链路 → 模型收不到搜索结果 → fetch_page 没机会被调用

质量第⑥层

B. Bing 中文多关键词拆词错误

"最近比较火的游戏" → Bing 把"最近"当作独立词条，返回百度百科释义和 2006 年李圣杰的歌。5 条结果没有一条关于游戏。

影响：即使不崩溃，搜索结果也没有价值

缺口第④层

C. 搜索失败后模型不补救

模型看到垃圾结果后说"不太对劲，又搜了一下"，但日志显示 has_tool_calls=false，它并没有真的再次调用 web_search 或 fetch_page。最终答案部分内容来自训练数据而非实时搜索。

影响：模型知道自己信息不足，但没有使用工具去弥补

已修未编第⑦层

D. fetch_page 结果不可见

web_search 写 last_search.txt，但 fetch_page 没有对应的落盘文件。补了一行 std::fs::write → last_fetch.txt，但还没重新编译跑过。
