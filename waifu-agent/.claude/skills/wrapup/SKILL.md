# /wrapup — 会话收尾

不只是盘点资产，更要让每次会话的教训自动转化成下次会话的能力。

## 1. 资产盘点

```bash
git status --short
```

列出所有未提交改动，生成 changelog 并直接 commit。

按文件路径判断文档归属：

| 路径 | commit 到 |
|------|----------|
| `D:\Projects\waifu-agent\docs\` | 项目仓库 |
| `D:\Docs\项目学习\` | 知识库仓库 |

> 判断标准：换项目时这份文档需要跟着走吗？要 → 知识库，不要 → 项目 docs/。

清理：
```bash
# Hook 脚本缓存
find .claude/hooks -name "__pycache__" -type d -exec rm -rf {} + 2>/dev/null
```
- **删除已执行完的计划文件**：`C:\Users\gaven\.claude\plans\*.md` 中本次的
- **检查 worktree 残留**：`git worktree list` — 没有用到的工作树提醒清理

## 2. 会话复盘

回顾本次会话，回答三个问题：

| 问题 | 回答格式 |
|------|---------|
| **什么地方花了不该花的时间？** | 具体场景 + 根因（如"调参 7 轮无效——不懂原理就改值"） |
| **什么知识缺口导致了问题？** | 缺失的知识点（如"不知道 inline style `background` 简写副作用"） |
| **如果重来一次，会怎么做？** | 一句话（如"先建实验室面板，再改代码"） |

回答完直接汇报给用户，不需要用户追问。

## 3. 知识路由

复盘产生的知识按性质分仓：

| 知识类型 | 落盘位置 | 判断标准 |
|---------|---------|---------|
| **机制级踩坑**（可复现、换人也踩） | `docs/技术参考/` + memory 短引用 | 人是第一读者 |
| **Claude 行为约束**（不要怎样写代码） | memory（`.claude/projects/.../memory/`） | Claude 是第一读者 |
| **架构决策** | `docs/技术参考/` | 长期参考 |
| **项目约定** | `CLAUDE.md` 或 `.claude/rules/` | 每次会话加载 |
| **用户偏好** | memory | 会话上下文 |

> 核心判断：**换一个 AI 工具来做这个项目，这份知识还需要吗？** 要 → docs/。只要 Claude 知道就行 → memory。

## 4. 系统进化

每次收尾必须问自己三个问题：

| 问题 | 处理 |
|------|------|
| **有没有重复出现的坑，值得写成 skill？** | 描述候选 skill 的职责和触发词，询问用户 |
| **有没有机器能自动拦的错误，值得加 hook？** | 描述 hook 的触发时机和检查逻辑，询问用户 |
| **有没有需要深度上下文的任务，值得拉 agent？** | 描述 agent 的职责，询问用户 |

**不一定每次都有答案，但必须问过。** 问过没有比不问强。

## 5. 下会话启动

不让下个 session 从零开始：

1. 读 `docs/项目规划/版本规划.md` 未修复列表，告知还有哪些待办
2. 告知本次产生的 docs 路径（下个 session 可以 `open docs/xxx`）
3. 列出现在需要用户决策的事项（不替他决定）

## 6. 未修复 bug / 未完成功能

写入 `docs/项目规划/版本规划.md`，不留在对话里——换 session 就丢了。

格式：
```markdown
| ⚠️N | 问题描述 | 影响 |
```
