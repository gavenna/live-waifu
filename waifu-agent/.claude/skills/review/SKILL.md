# /review — 体验审查

代码改动后的体验影响评估。你说"审一下"/"体验审查"/"有没问题"时触发。

## 自己能验的

| 维度 | 怎么验 | 工具 |
|------|--------|------|
| 贴图画面 | 读 `%APPDATA%/com.waifu-agent.app/stickers/*.png` | `Read` |
| TTS 清洗 | 构造含 `[tag]` 测试句 → STT 转写 → 对比 | `Bash` |
| 口型同步 | 日志时间戳：TTS 播放时长 vs 口型动画 | `Grep` |
| 对话质量 | 抽样对话日志，统计长度/套路/情绪多样性 | `Read` + `Grep` |
| 状态时序 | thinking→speaking→idle 间隔验证 | `Grep` |
| 窗口恢复 | settings.json 的 window.x/y 合理性 | `Read` |

## 不可自动验的（标出来给人看）

- 角色表情看起来自然吗？
- 贴图风格统一吗？
- TTS 声音好听吗？
- 整体交互感觉流畅吗？

## 报告格式

```markdown
### ✅ 自动验证通过
### ❌ 发现问题
### 👁 需人眼确认
```

## 关键纪律

- 结论必须有证据（代码行/日志/图片判断）
- 发现 bug 自己不修，报告就行
- 先验后报，验不了的才标记
