## 2. 启动 / 停止

```powershell
.\start-all.ps1                # 交互菜单
.\start-all.ps1 -All           # 全部启动
.\start-all.ps1 -Relay         # 只起中继（直播对战用这个）
.\start-all.ps1 -Waifu         # 只起伴侣应用
.\start-all.ps1 -Companion     # 只起抖音伴侣
.\start-all.ps1 -Status        # 看各服务状态
.\start-all.ps1 -Stop          # 全停并释放端口
```

被策略挡时：`powershell -ExecutionPolicy Bypass -File .\start-all.ps1`

启动后会打印并**自动打开浏览器**：
- 控制面板 `http://localhost:8767`
- 对战面板 `http://localhost:8767/battle.html`

> ⚠️ 中继必须通过 **`relay-window.bat`** 起（`start-all.ps1` 就是这么做的），因为它里面设了 `set RW_ECON_ENABLED=1` 等环境变量。用 `node index.js` 裸起会**丢掉经济开关**（退回免费召唤）。

## 3. 一局的生命周期

```
① 起局   POST /api/battle/start                     （默认地图 live_dire.tmx）
          ├ 从 mods/maps/ 复制地图到 assets 两处
          ├ 启动游戏（若未在跑）→ 等 Debug Socket :9999
          ├ 两遍 loadConfigAndStartNew（FFA / 7 个 AI）
          └ 关弹窗 → 进入对局
② 开战   round.startRound() → 状态 FIGHTING
          ├ 看门狗启动（每 5s 探测链路，连续 2 次失联才结束）
          └ 胜负轮询启动（轮询 isTeamDefeated）
③ 战斗中 观众弹幕 → 解析 → 读实时余额 → 扣款 → 生兵 → 播报
          （引擎每 6 帧把每队余额/收入落盘到 econ_live.txt，供中继读取）
④ 结算   引擎判定或超时 → 画面播报结果 → 状态回 IDLE
⑤ 下一局 **自动**：回 IDLE 后 `RW_AUTO_NEXT_MS`（默认 10s）自动开下一局
          （也可面板点「开始」/调 /api/battle/start；relay 以 `--auto-start` 启动时还会自动开第一局）
```

**关键状态**：`IDLE`（待命）/ `FIGHTING`（战斗中）/ `ENDED`（已结束）。
**待命时不处理弹幕** —— 想测弹幕必须先起局（见手册第 5 节）。

## 4. 日常运维要看的三样东西

| 看什么 | 路径 | 用途 |
|---|---|---|
| 中继日志 | `danmaku-relay/logs/combined.log` | 起局/生兵/扣款/拒绝/播报/失联，全在这（`[SPAWN]` `[ECON]` `[BATTLE]` `[播报]`） |
| 实时经济 | `<游戏目录>/econ_live.txt` | `# econ_live <毫秒> <帧>` + 每行 `team <id> <余额> <每秒收入>` |
| 游戏日志 | `<游戏目录>/lastrun.log` | 引擎自己的流水（起局流程、面板、崩溃、`Not showing defeated message` 等） |

**一键开关**（改 `relay-window.bat` 后重启中继生效）：

| 变量 | 默认 | 作用 |
|---|---|---|
| `RW_ECON_ENABLED` | `1` | `1`=召唤真扣钱；`0`=免费召唤（与接线前字节级一致） |
| `RW_ECON_MAX_AGE_MS` | 2000 | 经济数据过期阈值（超过就当读不到 → 拒绝召唤） |
| `RW_AUTO_START_ROUND` | `1` | relay `--auto-start` 就绪后**自动开第一局**（`0`=关，改为手动） |
| `RW_AUTO_NEXT_MS` | 10000 | 每局结束后**自动开下一局**的延时（`0`=关，回到手动点「开始」） |
| `RW_PUSH_LEVEL` | 2 | **收局推手挡位**：1=最轻(30s/1/20) · 2=中(20s/2/40) · 3=高(15s/3/60) · **4=最高(10s/4/100)**；下三项可单独覆盖对应旋钮 |
| `RW_PUSH_INTERVAL_MS` | 20000 | 推手周期：往两队无 AI 宿主队各补一批兵、落前线（`0`=关） |
| `RW_PUSH_UNITS` | 2 | 推手每次**每边**补几辆（两边恒等量，保证不偏袒任一方） |
| `RW_PUSH_TYPE` | tank | 推手兵种（中量级，避免一波平推；别填猛犸/超级） |
| `RW_PUSH_MAX_PER_SIDE` | 40 | 推手每边累计上限（防一方滚雪球平推） |
| `RW_ROUND_MAX_MS` | 300000 | 单局最大时长（毫秒，默认 5 分钟）；超时=平局，**直接决定直播节奏** |
| `RW_GAME_WATCHDOG_MS` | 5000 | 失联探测周期 |
| `RW_DEBUG_PORT` | 9999 | 游戏调试口 |
| `RW_DIR` / `RW_GAME_DIR` | 硬编码默认 | 游戏目录 |
| `RW_START_ENTRY` | `loadConfigAndStartNew` | 起局入口命令 |
| `RW_WAIFU_ENABLED` | `1` | 桌宠播报总开关；`0` = 关闭（只保留游戏内文字播报） |
| `RW_WAIFU_WS_URL` | `ws://127.0.0.1:9191/status` | 桌宠 relay 地址 |
| `RW_WAIFU_SPAWN_WINDOW_MS` | 1200 | 生兵播报合并窗口（窗口内多次召唤合并成一条，防 TTS 刷屏） |
| `RW_WAIFU_CHAT` | `1` | 观众对话开关（`0` = 只播报不对话） |
| `RW_LLM_API_KEY` | 空 | 观众对话所用 LLM 的 key（**留空 = 对话静默关闭**）；配了才启用 |
| `RW_LLM_API_URL` / `RW_LLM_MODEL` | deepseek | 对话 LLM 地址 / 模型 |
| `RW_CHAT_COOLDOWN_MS` | 8000 | 两条对话回复最小间隔 |
| `RW_LOG_FILE` | `logs/combined.log` | 日志文件路径（离线回归用它隔离测试输出，避免污染真实日志） |

1. **改 `danmaku-relay/**` 的任何 `.js`** ⇒ **必须重启中继**（这些文件只在启动时 require，热改无效）。

## 6. 引擎注入链路（改游戏本体，本项目的“超能力”来源）

游戏本身没有「读每队余额 / 显示双队经济条 / 精确加减钱」的脚本 API，这些是**改游戏 jar** 得到的。

```
war-vote/tools/_gfdec/game-lib.jar        ← 原始 jar（注入的输入，SHA256 8A550A37…DEEC9）
        │
        │  _reports/econ-research/_inject/build.ps1
        │   ├ [0] 清空 out/classes（**必须**，否则 javassist 会读到上次的 class 报 DuplicateMember）
        │   ├ [1] ECJ 3.21 编译 src/EconPatcher.java
        │   ├ [2] 游戏 JRE 跑 EconPatcher：javassist 注入
        │   │      · 新增 econinject.EconBridge（每 6 帧写 econ_live.txt / 画红蓝双条）
        │   │      · 新增 Debug.addTeamCredits(team,delta)
        │   │      · HUD 类 g.b(F)V 插调用 + 装“压制引擎原生经济行”的守卫
        │   └ [3] verify_static.py 静态校验（16 PASS / 0 FAIL）
        ▼
out/game-lib.patched.jar  ──►  复制到 <游戏目录>/game-lib.jar（**先备份原件**）
```

**部署（务必照做）**
1. 停游戏（`POST /api/battle/kill-game`），等几秒；
2. 备份：`game-lib.jar.bak-econ-<时间戳>`（已有若干份）；
3. 复制 patched jar 覆盖；
4. **核对 SHA256**：部署后的 `game-lib.jar` 必须与刚构建的 patched jar **一致**；
5. 起局复验。

> 🔴 **踩过的坑（务必记住）**：`build.ps1` 曾经因为 classpath 污染**静默失败** —— 产物停留在旧版本，而外层只看到"构建跑完了"，导致**连续部署三次旧 jar**。现已修（构建前清 `out/classes` + patcher 幂等）。**教训：部署前必须核对 sha256，别信"构建完成"这四个字。**

**回退**：把 `game-lib.jar.bak-econ-*` 复制回去即可（经济能力消失，且 `RW_ECON_ENABLED=0` 时中继行为本就与接线前一致）。

## 7. 地图维护

**成品地图**：`<游戏目录>/mods/maps/live_dire.tmx`（源：官方 `assets/maps/skirmish/[p2]Dire_Straight (2p) [by uber].tmx` 改造版）。
起局默认就是它（`battle/index.js` 的 `MAP_FILE_DEFAULT`）。

**改造配方**（`_reports/econ-research/_tools/` 里的脚本）：
- `fix_dire_teams.py`：重写 `Triggers` —— `map_info`（**必须保留 `winCondition=commandCenter`**）、只声明 **team 1（红，allyGroup 1）/ team 2（蓝，allyGroup 2）** 加一个 **team 0 席位**（`team_0_info`）。
- `team0_tiles.py strip|add`：控制 Units 层里 team 0 的基地瓦片（**默认 `strip`**）。
- Units 层是 **base64+gzip**；官方 2p 图自带的 2 组基地 = team0(510/515) + team1(555/560)，需要给 team2 时把 team0 那组**重映射成 591/596**。

**三条铁律**（都是实机踩出来的）：
1. **引擎的“你”永远是 team 0** —— 给它基地 ⇒ 不弹面板但画面变该队视角+迷雾；不给 ⇒ 观战全图但会弹模态 Defeat 面板。**用户要的是后者：只给 `team_0_info` 席位、不给单位**。
2. **基地必须建图时就写进 Units 层**，运行时 `createUnit` 补种**来不及**（引擎在 `loadConfig` 完成那刻就判定完，还可能弹**模态**面板卡死调试口）。
3. **别在已有基地的位置再种基地** —— 两个互为敌营的指挥中心会**互轰**炸掉一个，触发秒判负。

**换图的完整踩坑记录**：`_reports` + skill `live-waifu-ops/references/economy-and-hud.md` §P（含"失联误判"的根因与修法）。

## 8. 故障速查

| 症状 | 先看 | 常见原因 / 处理 |
|---|---|---|
| 弹幕发了没反应 | 中继日志有没有 `[SPAWN]`/`[ECON]` | ①是不是**待命状态**（IDLE 不处理弹幕）②阵营/兵种词不认识 ③同一观众 500ms 冷却 |
| 召唤被拒绝 | 日志 `[ECON] 拒绝召唤 … balance=…` | 该队余额不足（正常行为）；或用 `setTeamCredits` 补钱 |

## 10. 桌宠播报与对话（waifu-agent 接线，2026-09-20）

游戏事件与观众弹幕除了在**游戏画面内**播报（`debug.showMessage`），还会驱动 **Live2D 桌宠 waifu-agent 开口说话**（语音 + 表情 + 动作）。

```
battle/index.js   事件（开战 / 生兵 / 结算 / 观众闲聊）
      │ require
      ▼
battle/waifuAnnouncer.js   话术模板 + 生兵合并窗口（防 TTS 刷屏）
      │
battle/waifuBridge.js      WS 客户端 → ws://127.0.0.1:9191/status
      │  agent:start / agent:emotion / agent:motion / agent:end{synthesize:true}
      ▼
waifu-agent（:9191 ws_relay 把消息广播给房间内其他客户端）
      │
waifu 前端 App.tsx         收到 agent:end{synthesize} → 本地 edge-tts 合成 → 播放 + 口型 + 表情
```

- **谁出声**：音频由 **waifu 自己**用 edge-tts（`waifu-agent/src-tauri/python-embed`）合成；中继**不发音频**（base64 体积大），只发文本 + `synthesize:true`。TTS 归 waifu 职责 = 中继零 TTS 依赖。
- **对话**：`battle/waifuChat.js` 处理**非指令弹幕**（闲聊/问好，即 `parseDanmaku` 不认的那些）→ 调 LLM 生成一句回复 → 同样经 waifuBridge 播报。**需要配 LLM key**，否则静默关闭（不报错、不刷屏）。
  - key 放 `danmaku-relay\data\llm.json`（`{apiKey, apiUrl, model}`）——该目录已 `.gitignore`，**key 不会进 git**；也可用 `RW_LLM_API_KEY` 等环境变量覆盖（env 优先）。
  - 配置是**运行时**读取的 ⇒ 改 key/model **不用重启中继**。
  - 另一处（waifu 自身的内置聊天 LLM）配在 `%AppData%\com.waifu-agent.app\settings.json` 的 `llm` 段，**需要重启 waifu-agent 才生效**（前端启动时载入）。两处各配一次。
- **入场欢迎**：观众进直播间（适配器 `_enter` → `join` 事件）→ 桌宠念出**名字 + 阵营**并欢迎；玩法规则按 `RW_RULES_COOLDOWN_MS`（默认 90000ms）**节流**介绍，避免刷屏。`RW_WELCOME_ENABLED=0` 关闭；`RW_WELCOME_WINDOW_MS` 调合并窗口（默认 2500ms，短时间多个进场合併成一句）。
- **人格**：中继观众对话的人格在 `battle/waifuChat.js` 的 `PERSONA`（现为**女友风格**虚拟主播，全中文、不毒舌）；waifu 自身聊天的人格走 SOUL 预设（现 `soulPreset=mao-girlfriend`，文件 `waifu-agent\src\souls\mao-girlfriend.md`）。⚠️ **dev 模式下 SOUL 预设不生效**（`bundle.resources` 不含 souls、`target/debug/souls` 不存在 ⇒ `read_soul_file` 落到硬编码兜底）——要生效需同时放一份到 `%AppData%\com.waifu-agent.app\souls\<preset>.md`（`read_soul_file` 的第一优先级）。改 `soulPreset` 本身**不用重启**（Rust 每次对话现读 settings.json）。
- **玩法知识**：`battle/waifu-knowledge.md`（源：`docs/直播指令手册.md` 提炼）——`waifuChat` **运行时**读入并拼进 system prompt，让 AI 回答有据可依、不编造。改它**不用重启中继**。
