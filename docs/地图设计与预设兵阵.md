# 地图设计与"预设兵阵"指南（Rusted Warfare 1.15）

> 面向本项目（live-waifu 弹幕对战）的地图制作说明。
> 所有结论都注明来源：**官方文件** / **反编译源码行号** / **本项目实测**。未验证的会明确标注。

---

## 0. 一句话

地图是 **Tiled 格式的 `.tmx`**，五个图层各司其职；你想"预设好的兵阵"，就是往 **`Units` 图层**上刷带 `team` + `unit` 属性的图块。
`Triggers` 图层则负责规则（队伍、钱、胜负条件、镜头、事件）。

## 2. 五个图层的语义

官方 `custom_maps_readme.txt` 原文：

| 图层 | 官方说明 | 中文 |
|---|---|---|
| `set` | completely ignored by the game only used by Tiled for automapping (you should draw on this layer instead of ground) | 游戏**完全忽略**，只给 Tiled 自动映射用；**画地形要画这层** |
| `Triggers` | set map settings, players stats, and create events | 地图设置、玩家属性、事件 —— **规则都在这** |
| `Units` | setup starting units, anything else on this layer is ignored | **起手单位（= 预设兵阵）**，其它内容忽略 |
| `Items` | resource pools must go on this layer to work, trees and other items can appear on this layer. Do not use this layer for map tiles | 资源池必须放这层才生效；树等装饰也放这。**别拿它画地形**（会影响寻路） |
| `Ground` | map tiles go on this layer. But do not edit this layer if you are using automapping, as they will get overridden | 地形图块。用自动映射时**别手改这层**（会被覆盖） |

**实践结论**：地形用 `set` 层画（或 Tiled 自动映射生成），`Ground` 是引擎读的实体层；`Units` 摆兵；`Triggers` 写规则；`Items` 放资源池。

## 3. `Units` 图层 —— 预设兵阵的核心

### 3.1 编码规则

`Units` 层是 **base64 + gzip 压缩的 tile 数组**（每格一个 4 字节小端 gid）。
每格的 gid 指向 `units.tsx` 里的一个图块，而**每个图块自带 `team` + `unit` 两个属性**：

```xml
<tile id="51">
  <properties>
   <property name="team" value="1"/>
   <property name="unit" value="commandCenter"/>
  </properties>
</tile>
```

换算公式：

```
gid = 该地图里 units.tsx 的 firstgid + tile_id
```

> 🔴 **firstgid 是每张地图各自声明的，不能背成固定值**。
> 本项目实测（`grep '<tileset firstgid=.*units.tsx'`）：
> `live_dire.tmx` / `dire_stream.tmx` = **509**；另有 286 / 515 / 521 / 19 / 938 / 2 等，各不相同。
> 读 gid 前先 `grep firstgid` 拿这张图自己的值。
>
> 更坑的是：`live_dire.tmx` 里 **`units.tsx` 被引用了两次**（firstgid **509** 和 **938**），
> 在 Tiled 里同一个兵会出现两个调色板条目 —— 刷出来哪个 gid 取决于你点了哪个。
> 引擎两者都认（同一份 tsx），但**按 `509+id` 写死的脚本会漏掉 938 系列的格子**。

## 4. `Triggers` 图层 —— 规则与事件

### 4.1 引擎认识的对象类型

反编译取证：`war-vote\tools\_gfdec\gf_src\com\corrodinggames\rts\gameFramework\n\f.java`
（`equalsIgnoreCase` 扫描结果）：

```
map_info, team_info, point, camera_start, camera_pan, attack_point,
rotate, fall, set_team, ai_allow_full_use, disable_unit_ai, info
```

`type` 的取值另有 `skirmish` / `survival`。

### 4.2 `map_info`（**必需**，缺了会报错）

同文件日志文本：`Error: map_info is missing from this map`、`Error: 'triggers' object layer is missing from this map`、`Defaulting to skirmish`。

| 属性 | 说明 | 取值 |
|---|---|---|
| `type` | 对局类型 | `skirmish`（对战）/ `mission` / `survival` |
| `winCondition` | 胜负判定 | `commandCenter`（拆指挥中心）/ `mainBuilings` / `none`（不判）|
| `fog` | 战争迷雾 | `map`（有雾）/ `none`（全图可见，观战用）|
| `introText` | 开局提示文字 | 任意字符串 |

> `winCondition` 缺失的后果：引擎回落到"以本地玩家 team 0 为参照"的默认判定，
> team0 没基地 ⇒ **一进游戏就弹 Defeat 面板**。本项目的 `live_dire.tmx` 有实测记录（脚本注释）。

### 4.3 `team_N_info`（`type="team_info"`）

| 属性 | 说明 |
|---|---|
| `team` | 队号（0–9） |
| `credits` | 开局资金 |
| `allyGroup` | 同盟组号（同号即同盟） |
| `disabledAI` | **禁用该队 AI**（本项目的核心机制） |
| `ai` / `basicAI` / `lockAiDifficulty` | AI 行为与难度 |
| `shareFogWithAllies` | 与盟友共享视野 |
| `startWithMusic` | 开局音乐 |
| `survivalWaves` / `survivalWavesClassic` | 生存模式波次 |

**`disabledAI` 的实测证据**（我本轮读源码确认）：
`f.java:349-353`
```java

    ...l.b("Disabling AI:" + n2 + " by map request");
    a2.aX = true;

```
置 `aX = true` 后该队 AI 每帧更新入口直接早退、不下任何命令 —— 所以落在这队上的脚本命令不会被 AI 覆盖。项目用它把 team3/team4 变成"无 AI 宿主队"。

### 4.4 `camera_start`（开局镜头）

`f.java:362-369`（实测确认）：

### 4.5 事件链

| 属性 | 作用 |
|---|---|
| `activateIds` / `alsoActivate` | 激活其它触发器 |
| `activatedBy` / `deactivatedBy` / `whenActivatedIds` | 被谁激活/停用 |
| `dir` / `index` / `Briefing` | 方向 / 序号 / 简报 |

配合 `point` / `attack_point` / `camera_pan` / `rotate` / `fall` / `set_team` /
`ai_allow_full_use` / `disable_unit_ai` / `info` 这些对象类型，可以编排出**脚本化的事件剧本**（官方 `example_mission.tmx` 就是范例）。

> ⚠️ 未验证项：`fog` 属性的解析**不在** `f.java` 里（本项目脚本注释指向 `game\b\b.java:1020-1037`），我这轮**没有核实那一处**。

## 5. 两条实现路径

### 路径 A：Tiled 手绘（适合地形/美术）

1. 用 Tiled 打开 `mods\maps\live_dire.tmx`（或复制官方图另存为新名）。
2. `set` 层画地形 → 自动映射生成 `Ground`。
3. `Items` 层刷资源池（`units.tsx` 的 `extractor` 是建筑，资源池走 `Items` 层/官方 tileset）。
4. `Units` 层刷基地与预设兵阵 —— 注意每个兵都要选**正确队伍**的图块（Tiled 里同名的兵有 10 个队伍的版本）。
5. `Triggers` 层放 `map_info` / `team_N_info` / `camera_start`。
6. 保存 → 重启中继 → 起局验证。

### 路径 B：程序化生成（适合"参数化兵阵"、可复现、可回归）

项目已有现成积木，直接复用：

| 工具 | 位置 | 用途 |
|---|---|---|
| `analyze_map.py` | `_archive\ccresearch-game\` | 只读解析任意 tmx 的 `Units` 层并列出非空瓦片（`from analyze_map import get_layer, layer_width` 可复用） |
| `build_stream_map.py` | `_archive\ccresearch-game\` | **全流程范例**：从官方图确定性重建 livestream 地图 + 自带 `check` 模式（源与产物漂移即 exit 1） |
| `dump_units_layer2.py` / `team0_tiles.py` / `fix_dire_teams.py` | `_reports\econ-research\_tools\` | 解层 / 增删队伍基地瓦片 / 重写 Triggers |

**写一个"兵阵脚本"的推荐形态**（照 `build_stream_map.py` 的骨架）：

```python
# 1. 读源 tmx，解 Units 层的 base64+gzip -> gids
# 2. 按 (x, y, team, unit) 列表写 gid = firstgid + tile_id[x]
#    firstgid 从文本里 grep 出来，不要写死
# 3. 重新 gzip.compress(..., mtime=0) + base64 写回（mtime=0 保证可复现）
# 4. 自带 verify：重新解析一遍，断言 (x,y)->gid 与预期一致；断言其它层字节未变
```

**判定新代码是否生效的硬锚点**：`analyze_map.py <tmx>` 输出的非空瓦片清单（而不是"看起来对不对"）。

## 6. 本项目铁律（踩过的坑，别再来一次）

1. **team 0 不能给单位**。引擎的"你"永远是 team 0；给它基地 ⇒ 画面变该队视角+迷雾；不给 ⇒ 观战全图（本项目要的）。
   反编译取证（本轮实测）：`game\b\g.java:114-117` —— 观战队（spectator）的单位会被**直接丢弃**并记日志
   `Unit team is marked as spectator: ... (skipping unit)`。
2. **基地必须建图时就写进 `Units` 层**，运行时 `createUnit` 补种来不及（引擎在 `loadConfig` 完成那刻就判定完了）。
3. **别在已有基地的位置再种基地** —— 两个互为敌营的指挥中心会互轰，炸掉一个即秒判负。
4. **`winCondition` 必须保留**（见 §4.2）。
5. **队号与地图绑定**：改 team3/4 的队号必须**同时**改地图 `team_N_info` 与 `danmaku-relay\battle\teams.js:34-35`。
6. **文件名不能带 `[pN]` 前缀**。反编译取证（本轮实测 `appFramework\i.java:95-100`）：
   ```java
   int n8 = n.c - 1;
   int n9 = com.corrodinggames.rts.appFramework.c.a(string2);   // 从文件名解析 [pN]
   l.e("Max teams on map: " + string2 + " = " + n9);
   if (n9 > 0 && n9 - 1 < n8) { n8 = n9 - 1; }
   ```
   → `[p2]` 会把队伍数上限压到 1 支 AI，多阵营对战直接不可能。`live_dire.tmx` 故意没有前缀。
7. **改完必须重启中继**（地图在起局时才被拷进 `assets`）。
8. **`mods\maps` 是源**，`assets\maps\skirmish` 是产物（见 §1）。
9. **产物不要散到工作区外**（项目硬约束）；地图源文件例外，它天生在游戏目录里。

## 7. 已知陷阱与不一致（本轮实测发现）
