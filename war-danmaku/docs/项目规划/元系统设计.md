> 最后更新: 2026-06-30

本文档记录**开发环境本身的架构**——Claude Code 怎么理解这个项目、怎么记住偏好、怎么拦住错误。

## 整体层次

```
用户
  │
  ├─ Harness (settings.local.json)     ← 自动化检查，拦错误
  │
  ├─ CLAUDE.md                         ← 项目入口：技术栈、命令、铁律
  │   └─ .claude/rules/                ← 专项规则：git、cubism

  ├─ Auto-Memory (~/.claude/projects/) ← Claude 跨会话记住你的偏好
  │
  └─ 项目代码                           ← 被修改的对象
```

## 三、Harness Hooks（自动化检查，不进 git）

**位置**：`D:\Projects\waifu-agent\.claude\settings.local.json` + `.claude/hooks/`

**不在 git 里**（`settings.local.json` 被 `.gitignore`），每个开发者可以有自己的 hook 配置。

### 3.1 PreToolUse（工具执行前）

| 脚本 | matcher | 做什么 | 拦截？ |
|------|---------|--------|:--:|
| `check-catch-silence.py` | Edit\|Write | 检查 TS/JS 文件是否新增 `.catch(() => {})` 静默吞错 | **是**（发现才拦） |

**拦截逻辑**：只拦能定位到文件路径的 TS/JS 编辑。检查 `new_string` 是否包含 `catch(()) => {}` ——有就返回 2 让 AI 改成 `catch(e => console.error(..., e))`。

### 3.2 PostToolUse（工具执行后）

| 脚本 | 做什么 | 影响 |
|------|--------|------|
| `validate-settings.py` | 检查 `settings.json` 的 `character.scale` 是否被误重置为 0.25 | 仅警告 |
| `check-tts-pipeline.py` | git diff 中检测新 `[tag]`/`【tag】` 语法 → 提醒同步更新 `cleanTtsText` | 仅警告 |

### 3.3 Stop（会话结束或暂停时）

| 命令 | 作用 |
|------|------|
| `cargo check \| tail -1` | Rust 编译状态提示 |
| `tsc --noEmit \| head -3` | TypeScript 错误提示 |

### 3.4 关键理解

- **Hook 只拦一种代码错误**（静默吞错），不是审查所有变更
- **PostToolUse 只警告，不拦截**——你不能靠 hook 阻止 AI 写烂代码，hook 只是提醒
- **Hook 脚本的 cwd 是项目根目录**（之前路径 `../.claude/hooks/` 多写了个 `..` 导致脚本找不到，已修复为 `.claude/hooks/`）

## 四、Auto-Memory（跨会话偏好，不进项目 git）

**位置**：`C:\Users\gaven\.claude\projects\D--Projects-waifu-agent\memory\`

**索引**：`MEMORY.md`（每次会话加载到上下文）

**职责**：记住关于**开发者本人**和**开发偏好**的信息，跨会话持久化。

### 4.1 内容类型

| 类型 | 说明 | 示例 |
|------|------|------|
| `user` | 开发者身份、偏好 | 客户会议风格：结论先行 |
| `feedback` | 对 AI 工作方式的纠正 | 方案类改动必须先陈明利弊 |
| `project` | 项目目标、约束 | Bug 修复后 commit 附根因分析 |
| `reference` | 外部链接、资源 | Cloudflare 域名配置详情 |

### 4.2 与 CLAUDE.md 的分工

| | CLAUDE.md | Auto-Memory |
|---|---|---|
| **存什么** | 项目技术事实（怎么写代码） | 用户偏好（你希望 AI 怎么工作） |
| **谁维护** | 开发者手动更新 | AI 根据对话自动沉淀 |
| **跟项目走？** | 是（git） | 否（本地） |
| **触发方式** | 每次会话自动加载 | 对话中提到时加载相关 memory |

### 4.3 写入规则

- 需要在 memory/ 下新建 `.md` 文件，带 frontmatter
- 写之前先查 MEMORY.md 是否有重复 → 有则更新，无则新建
- 不存代码结构、git 历史、CLAUDE.md 已有内容
- 每次写入必须通报内容+位置

**当前（2026-06-29）有 25 条 memory，覆盖**：
- 工作流程：bug 修复规范、场景验证、决策流程
- 沟通风格：结论先行、不辩护、不展开猜测
- 技术纪律：修根因不堵出口、诊断工具先验证、事件单一职责
- 运维：Vercel 部署、Cloudflare 域名

## 五、角色记忆系统（waifu-agent 产品功能）

这部分是**产品代码的一部分**，跟上面四个不同——它是 waifu-agent 的运行时功能，不是 Claude Code 的配置。

### 5.1 层次

```
prompt 构造顺序（每次对话）:
  SOUL.md        ← 角色气质/态度（仅定义她是谁）
  记忆边界规则    ← "记忆区空=你不了解主人"
  USER.md        ← 用户画像（固定文本）
  MEMORY.md      ← 用户显式"记住"的内容
  相关记忆        ← memory_recall(query, topK=8) 关键词匹配
  工具说明        ← web_search / read_clipboard / system_info
```

### 5.2 存储

```
app_data_dir/
  SOUL.md          ← 用户自定义角色卡（可选，覆盖内置预设）
  USER.md          ← 用户画像文本
  MEMORY.md        ← 显式 "记住" 列表
  portrait.json     ← 画像原始答案
  history.json      ← 最近 10 轮对话
  conversations/    ← 每日对话日志 JSONL
  settings.json     ← 运行时设置（含 soulPreset）

  memory/
    thoughts.jsonl  ← 蒸馏的角色念头（目前退化，不再注入 prompt）
    mao/
      facts.json    ← 事实存储（extract → absorb → persona）
      persona.json  ← 人格事实（已吸收，目前不再注入 prompt）
```

### 5.3 命令

| 命令 | 触发 | 作用 |
|------|------|------|
| `memory_configure` | 启动时 | 初始化 Python memory 管线 |
| `distill_memory` | 启动时 | 蒸馏最近对话→thoughts |
| `memory_recall` | 每条消息前 | 关键词匹配 top-8 事实 |
| `memory_extract` | 每条消息后 | 后台提取新事实 |
| `append_memory` | 用户说"记住"时 | LLM 提炼→写入 MEMORY.md |
| `clear_memory` | 手动 | 清空 memory/ + conversations/ + history.json + portrait.json + USER.md + MEMORY.md + SOUL.md |

### 5.4 SOUL 预设

**位置**：`src/souls/`（5 套，开发期从源码读，生产期从 resource dir 读）

| 文件 | 气质 | ~字数 |
|------|------|------|
| `mao-teasing.md` | 毒舌傲娇 | 180 字 |
| `mao-warm.md` | 安静陪伴 | 150 字 |
| `mao-cool.md` | 冷淡观察 | 150 字 |
| `mao-energetic.md` | 元气话痨 | 180 字 |
| `mao-rebel.md` | 反叛挑战 | 150 字 |

**选择方式**：设置面板 → `soulPreset` → 下次对话生效（不重启）

**加载优先级**：
1. `app_data_dir/souls/{preset}.md` — 用户可编辑覆盖
2. `app_data_dir/SOUL.md` — 旧版兼容
3. 项目源码 `src/souls/{preset}.md` — 开发期
4. Tauri resource dir — 生产期
5. 内置 3 行 fallback

### 5.5 设计原则（从踩坑中总结）

1. **SOUL.md 只定义"她是谁"，不虚构用户细节**——之前写"主人加班她会调侃"导致 LLM 自行编造用户习惯
2. **记忆区空 = 角色不了解主人**——有硬约束，防止 LLM 从角色设定反推用户信息
3. **相关性召回 > 全量注入**——之前 persona + thoughts 全塞进 prompt 导致噪音淹没信号
4. **提取≠记忆**——extract 从对话提取事实，recall 按话题召回，是两个独立步骤
