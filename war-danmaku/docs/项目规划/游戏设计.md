# 阵营对抗弹幕游戏 — 中世纪战争

> 决策：中世纪战争题材 · 真人主播 · 抖音平台 · 纯 Web Canvas
> 第一版目标：主播能开播，观众能玩，能收礼物。

---

## 一、题材定位：中世纪战争

### 为什么选这个

- 兵临城下（同题材）已验证月流水 6000 万+，市场不需要教育
- 兵种克制链天然清晰（盾→枪→骑→弓→攻城器械→传说生物）
- 画面冲击力强，两军对垒天然适合直播展示
- 25-40 岁男性核心受众对战争题材有天然的代入感
- 抖音上该题材仍有空间——现有产品美术普遍粗糙，好画面 = 竞争力

### 世界观

两个王国争夺边境要塞。红方 = 炎龙帝国，蓝方 = 霜狼联盟。每局是一场攻城战。

## 二、核心游戏循环

### 2.1 单局流程

```
准备阶段（30秒）
  → 弹幕"红"/"1"= 炎龙帝国  |  "蓝"/"2"= 霜狼联盟
  → 已有观众可提前点赞/送礼积蓄兵力
  → 画面显示双方当前人数 + 战力预估

战斗阶段（15~20分钟）
  → 双方自动出兵，战线碰撞推进
  → 目标：摧毁对方城堡（HP 10000）
  → 点赞/弹幕/送礼 = 出兵/增益

结算阶段（20秒）
  → 胜方占领城堡动画 + MVP 展示
  → 个人积分入账 + 排行榜刷新
  → 倒计时自动下一局
```

## 三、兵种体系（= 付费阶梯）

### 3.1 完整兵种树

```
【免费层】零门槛参与 — 4 兵种克制闭环
  弹幕「杀」/「666」 → 3 名民兵（伤害 1 / HP 50，克突袭兵）
  弹幕「枪」        → 2 名矛兵（伤害 2 / HP 45，克民兵）
  弹幕「射」        → 2 名弓兵（伤害 1.5 / HP 30，远程 200px，克矛兵）
  弹幕「袭」/「冲」 → 2 名突袭兵（伤害 2.5 / HP 35，速 2.2，克弓兵）
  克制链：民兵→突袭兵→弓兵→矛兵→民兵（闭环，克制伤害 ×2）
  弹幕「赞」（抖音点赞）→ 3 名民兵

【入门层】~1 元以下，让观众体验"花钱有效果"
  小❤️（1抖币）    → 3 名剑士（伤害 3 / HP 150）
  棒棒糖（5抖币）   → 1 名重装骑士（伤害 12 / HP 400，冲撞效果）

【进阶层】1~10 元，主力小额消费
  鲜花（10抖币）    → 5 名长弓手（伤害 20 / HP 125，远程）
  铁锤（30抖币）    → 1 台投石车（伤害 60 / HP 250，AOE，攻击敌方后排）

【核心层】10~100 元 ★★★★ 营收主力区间
  盾墙（99抖币）    → 10 名皇家卫队（伤害 100 / HP 1000，带护盾吸收伤害）
                     附带：送礼者头像显示在兵种上方
  火矢齐射（199抖币）→ 全场箭雨（敌方全体伤害 500 + 减速 30%，8秒）
  攻城锤（299抖币）  → 对城堡直接造成 1500 伤害 + 显示送礼者头像

【顶级层】100~500 元 ★★★★★ 大哥专区
  召唤巨人（520抖币） → 1 名岩石巨人（伤害 500 / HP 2500，范围攻击，巨幅头像）
  龙骑士（1200抖币）  → 1 名龙骑士（伤害 1000 / HP 5000，全屏威慑，敌方小兵恐惧3秒）
                       附带：全屏横幅"XXX 召唤了龙骑士！"
  天神之怒（3000抖币）→ 全屏技能，伤害 8000 + 敌方城堡直接 -20% 血量
                       附带：专属动画 + 全局播报

【盲盒层】随机性 = 重复消费
  战争宝箱（99抖币）  → 随机：剑士队 / 投石车 / 皇家卫队 / 巨人 / 龙骑士

> **数值设计说明 (2026-07-15 调整)**: HP 全线 ×5、高费兵伤害 ÷2，目的是延长战斗时间，让四态程序化动画（idle→walk→attack→death）有足够时间展示。民兵对砍约 5 秒才死。
```

### 3.2 头像展示——付费核心驱动力

这是整个游戏最重要的设计。兵临城下验证了：**大哥刷礼物不是为了赢，是为了让别人看到自己。**

| 兵种级别 | 头像大小 | 停留时间 | 附加效果 |
|---------|---------|---------|---------|
| 皇家卫队（99抖币） | 小头像 | 5 秒 | 跟随兵种移动 |
| 攻城锤（299抖币） | 中头像 | 8 秒 | + 横幅播报 |
| 岩石巨人（520抖币） | 大头像 | 12 秒 | + 兵种身上显示名字 |
| 龙骑士（1200抖币） | 巨幅头像 | 全屏展示 3 秒 | + 全屏动画 + 全局播报 |
| 天神之怒（3000抖币） | 全屏专属动画 | 5 秒 | + 弹幕区置顶公告 |

**设计原则**：越贵的礼物 → 头像越大 → 停留越久 → 看到的人越多 → 大哥越爽。

### 3.3 兵种克制链

**免费四兵种闭环**（观众零门槛参与，战略性选择）：
```
民兵 ─克→ 突袭兵 ─克→ 弓兵 ─克→ 矛兵 ─克→ 民兵
```

**全兵种克制关系**：
```
民兵        克   突袭兵           人海挡冲锋
矛兵        克   民兵             长枪扫步兵
弓兵        克   矛兵             远程风筝  
突袭兵      克   弓兵             速度近身
剑士        克   民兵 + 矛兵      精兵碾压基础兵
骑士        克   剑士 + 弓手      冲锋穿透
弓手        克   骑士             远程先手
投石车      克   弓手 + 后排      AOE 溅射
皇家卫队    克   骑士 + 弓手      护盾吸收
巨人        克   所有地面兵种     范围碾压
龙骑士      克   巨人 + 城堡      恐惧 + 高伤
```

克制关系的存在让战斗不是纯数字碾压——花钱多的理论占优，但用对兵种的小R也能打出效果。**不能让小R觉得"不充钱就没用"，否则他们会走。**

## 四、积分与荣誉系统

### 4.1 积分获取

| 行为 | 积分 | 设计意图 |
|------|------|---------|
| 击杀敌方小兵 | +10/个 | 免费层的主要积分来源 |
| 对城堡造成伤害 | 伤害值/10 | 推塔有奖励 |
| 连杀 ×5 | 积分 ×1.5 | 鼓励持续参与 |
| 连杀 ×10 | 积分 ×2.0 | |
| 本局胜利方全员 | +200 | 归属感奖励 |
| MVP（胜方最高伤害） | +500 | 个人荣誉 |
| SVP（败方最高伤害） | +300 | 败方不白打 |
| 送礼额外积分 | 礼物价值 ×3 | 付费加速 |

### 4.2 军衔系统（段位 = 长期留存）

```
军衔          积分门槛    特权
新兵            0        无
老兵          500        名字颜色变化
十夫长       2000        入场提示 + 民兵伤害 ×1.5
百夫长       8000        所有基础兵种伤害 +10%
千夫长      20000        专属头像框 + 皇家卫队伤害 +20%

元帅       100000        定制称号 + 连杀全屏播报 + 龙骑士伤害 +50%
```

活跃玩家不付费也能在 2 周内升到百夫长。千夫长以上基本需要付费。

### 4.3 排行榜

| 排行 | 周期 | 作用 |
|------|------|------|
| 本局贡献榜 | 当前 | 主播每 30 秒念一次，刺激实时消费 |
| 日榜 | 每日 | 当日荣耀 |

## 五、主播话术系统

真人主播是这个游戏引擎的"点火器"。数值设计再好，主播不说话 = 没人消费。

### 5.1 完整话术节奏

```
【开场拉人】前 3 分钟
目标：让路人选阵营、点关注
"欢迎各位将军！炎龙还是霜狼？弹幕打 1 加入红方，打 2 加入蓝方！"
"看看今天哪边的将军多！"

【战况播报】每 30 秒
目标：维持注意力，制造紧张
"红方战线推到中线了！蓝方后撤了！"
"蓝方破军已经杀了 23 个，红方谁能拦住他？"

【即时感谢】送礼 3 秒内
目标：让付费者立刻得到正反馈
"感谢战歌的龙骑士！！！蓝方直接起飞，这一波红方怎么接？！"

【激将/拱火】劣势方时（核心营收动作）
目标：刺激劣势方消费
"炎龙帝国基地只剩 3000 血了！将军们，城破就是亡国！"
"对面破军都杀穿了，红方有没有大将能制裁他？"
"还差 1500 伤害翻盘！一组攻城锤就能逆转！"

【最后 2 分钟】决胜期（付费峰值）
目标：双方对刷
"最后一分钟！！红方领先 2000 血，蓝方还有机会！"
"天神之怒直接带走！有没有大哥？最后的机会！"

【结算】20 秒
目标：念榜留人，引导下一局
"恭喜炎龙帝国！！战歌 12500 分 MVP，破军 10800 分 SVP！"
"20 秒后下一局，想赢的叫人！分享直播间喊兄弟来！"
```

### 5.2 主播不需要什么

- **不需要才艺**：不用唱歌跳舞，战场就是内容
- **不需要颜值**：可以不露脸，游戏画面就是直播内容
- **不需要粉丝基础**：游戏自带内容，路人看到画面就懂
- **只需要**：会解说、会念名字、会拱火

## 六、数值平衡

### 6.1 动态平衡机制

| 机制 | 触发条件 | 效果 |
|------|---------|------|
| 人数平衡 | 红蓝人数差 > 2:1 | 少数方伤害 +20%~50% |
| 劣势鼓舞 | 一方城堡 HP < 30% | 该方伤害 +15% |
| 碾压加速 | 一方 HP > 80% 且持续 5 分钟 | 优势方伤害 +10%，快速结束一边倒 |
| 大哥对冲提示 | 单方连续 3 次大额送礼 | 系统播报"炎龙帝国已集结主力！霜狼联盟请迎战！" |

### 6.1.1 战斗动画系统（Phase 6 新增）

兵种四态程序化动画，由 Server 判定 animState，前端纯代码渲染（不依赖额外素材）：

| 状态 | 效果 | 触发条件 |
|------|------|---------|
| idle | 呼吸缩放 ±3%，600ms 周期 | 出生后 600ms 内 |
| walk | 上下弹跳 2px + 微倾斜 0.04rad | 移动中，无敌人 |
| attack | 前冲 5px → 回退，480ms 周期 | 敌人在 78px 内 |
| death | 下沉 + 缩小 40% + 渐隐 + 旋转倒下，720ms | HP ≤ 0 |

**接敌停止**: 兵种前方 60px 有敌人时停止移动，原地交战。进入 78px 范围时双方先切 attack 动画，到达 60px 后开始扣血。避免"擦肩而过"。

### 6.2 单局时长

```
目标：15~20 分钟
最短：10 分钟（实力悬殊，碾压加速生效）
最长：30 分钟（超时以城堡血量判定胜负）
```

## 七、技术方案（纯 Web Canvas）

### 7.1 为什么不用 Cocos/Unity

- 学习成本：Cocos Creator 需要学一套引擎体系，Canvas 纯手写
- 迭代速度：改一个动画效果，Canvas 改 JS 就行，Cocos 要重构建
- OBS 兼容：浏览器窗口直接捕获，不需要额外配置
- 人手：一个人开发，不需要引擎的项目管理能力

### 7.2 架构

```
┌─────────────────────────────────────────┐
│  抖音直播间                              │
│  ┌──────────────────────────────────┐   │
│  │  OBS / 直播伴侣                   │   │
│  │  ┌────────────────────────────┐  │   │
│  │  │  浏览器源 (Web Canvas)      │  │   │
│  │  │  - 战斗画面                 │  │   │
│  │  │  - 排行 + 弹幕滚动          │  │   │
│  │  └──────────┬─────────────────┘  │   │
│  │             │ WebSocket           │   │
│  └─────────────┼────────────────────┘   │
└────────────────┼────────────────────────┘
                 │
┌────────────────┼────────────────────────┐
│  游戏服务器 (Node.js)                    │
│  ┌─────────────┴─────────────────────┐  │
│  │  WebSocket Server                 │  │
│  │  - 推送游戏状态到前端              │  │
│  │  - 接收前端事件                    │  │
│  ├───────────────────────────────────┤  │
│  │  Game Engine                      │  │
│  │  - 兵种生成与交战                  │  │
│  │  - 战线推进计算                   │  │
│  │  - 积分/排行/段位                  │  │
│  ├───────────────────────────────────┤  │
│  │  Danmaku Adapter                  │  │
│  │  - 抖音弹幕接入（第三方工具/API）  │  │
│  │  - 礼物映射到兵种                  │  │
│  └───────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

### 7.3 为什么后端选 Node.js 而不是 Python

之前的方案推荐 Python（因为有弹幕协议库），但现在明确了抖音平台 + 真人主播：

- **抖音弹幕数据走第三方工具**（如可遇AI弹幕工具、抖音直播伴侣SDK），不需要自己写协议逆向
- Node.js 前后端同语言（JS），一个人开发上下文切换成本低
- WebSocket 在 Node.js 生态最成熟（ws / socket.io）
- 前端 Canvas 渲染逻辑可以和后端游戏逻辑共享类型定义

### 7.4 弹幕接入方案（抖音）

**开发/测试期**：
- 用 B站开放协议（blivedm 库）调试游戏逻辑，B站弹幕协议完全开放
- 游戏跑通后再对接抖音

**正式上线**：
- 方案A：抖音直播伴侣 + 小玩法 SDK（官方路线，需要软著+审核）
- 方案B：第三方弹幕工具（如可遇AI）→ WebSocket 转发 → 游戏服务器
- 推荐：先方案B快速验证，跑出数据再走方案A上架

## 九、开发阶段

### Phase 1：骨架（3~5 天）
- WebSocket 服务 + 前端 Canvas 通信
- 战斗引擎（自动出兵 + 战线推进 + 城堡伤害）
- B站弹幕接入（开发调试用）

- 礼物映射到兵种
- 头像展示系统
- 弹幕指令（点赞/「杀」/「冲」）
- 积分 + 排行榜

### Phase 3：美术 + 体验（3~5 天）
- AI 生成兵种精灵图（民兵/剑士/骑士/弓手/巨人/龙）
- 城堡、战场背景
- 特效（冲锋、攻城、龙焰、天神之怒）
- OBS 适配（分辨率、布局）

### Phase 4：抖音对接 + 上线测试（2~3 天）
- 抖音弹幕接入
- 真实直播测试
- 话术打磨 + 数值调优
