# 使用指南

## 快速体验（一键启动）

```powershell
.\start.ps1
# 自动启动服务端 + 弹幕中继（如已配置）
# 浏览器 http://localhost:8765
# 右侧控制面板按钮操控
# 关闭窗口即可停止全部
```

如果没配 B站，`start.sh` 只启游戏服务端，弹幕中继自动跳过。

---

## B站直播接入

1. 编辑 `server/secrets.json`：
```json
"bilibili": { "roomId": 123456, "sessdata": "你的Cookie" }
```
2. `pip install blivedm websocket-client`（首次）
3. `bash start.sh` — 自动启动服务端 + 弹幕中继
4. 在 B站直播间发弹幕 `1` `杀` `666` `冲` 即可操控游戏

---

## 手动控制（模拟器，无需弹幕）

```bash
node server/simulator.js
```

连上 WebSocket 后，逐条输入指令控制游戏：

```
join red          # 加入炎龙帝国（红方）
join blue         # 加入霜狼联盟（蓝方）
red / 1           # 快捷加入红方
blue / 2          # 快捷加入蓝方
gift knight       # 送礼 → 1 名骑士（5 抖币）
gift giant        # 送礼 → 1 名岩石巨人（520 抖币）
gift dragonKnight # 送礼 → 1 名龙骑士（1200 抖币）
gift wrathOfGod   # 送礼 → 天神之怒（3000 抖币）
gift warChest     # 送礼 → 战争宝箱盲盒（99 抖币）
danmaku 杀        # 弹幕"杀"→ 3 名民兵
danmaku 冲        # 弹幕"冲"→ 全体友军加速
danmaku 任意文本  # 普通弹幕，显示在画面底部滚动区
status            # 查看连接状态
help              # 显示完整指令列表
exit              # 退出
```

### 可用兵种 key

`militia` `swordsman` `knight` `archer` `catapult` `royalGuard` `giant` `dragonKnight` `fireArrow` `batteringRam` `wrathOfGod` `warChest`

### 测试流程建议

1. 开两个终端，各跑一个 `node server/simulator.js`（模拟两个玩家）
2. 一个 `join red`，一个 `join blue`
3. 等 COUNTDOWN 结束进入 PLAYING
4. 双方交替发 `gift` 出兵，看战线拉锯
5. 模拟大哥出手：`gift dragonKnight` 或 `gift wrathOfGod`

## 日志系统

### 开关控制

在 `server/config.js` 的 `LOG` 块里按需开关：

```js
LOG: {
  LEVEL: 'DEBUG',       // 全局级别: DEBUG | INFO | WARN | ERROR
  TAGS: {
    WS: true,           // WebSocket 连接
    ENGINE: true,       // 游戏状态机
    BATTLE: true,       // 战斗计算（高频，可关）
    DANMAKU: true,      // 弹幕处理
    RANKING: true,      // 积分/排行
    GIFT: true,         // 礼物处理
    SERVER: true,       // 服务器启动
    SIMULATOR: true,    // 模拟器
  },
  TO_FILE: true,        // 写文件
  TO_CONSOLE: true,     // 终端输出
},
```

- 关掉某个 tag → 该类型的日志不再出现
- `LEVEL: 'WARN'` → 只显示 WARN 和 ERROR
- 战斗层高频日志不刷屏，只记关键事件

### 日志文件

每次启动在 `server/logs/` 下生成：
- `session-YYYYMMDD-HHmmss.log` — 当次会话完整日志
- `error.log` — 所有 ERROR 级别日志汇集

## 出了 bug 怎么查

### 标准流程

1. **看 error.log** — 有没有直接报错？先搜 `[ERROR]`
2. **没问题 → 定位层**：
   - 弹幕没反应？ → 开 `DANMAKU: true`，看日志有没有收到指令
   - 兵种不动？ → 开 `BATTLE: true`，看 tick 里的数据
   - 积分没变？ → 开 `RANKING: true`，看结算逻辑
   - 前端不显示？ → 开 `WS: true`，看广播数据
3. **日志不够细** → 把 `LEVEL` 设为 `DEBUG`，重现一次
4. **日志看不出** → 在怀疑的节点加 `assert()`，逐个用断言定位
5. **找到根因** → 修 → 补日志 → 写 `docs/bugs/` 沉淀

### 常见问题

**Q: 改了 config.js 不生效？**  
A: 需要重启 server。config 不热更新。

**Q: OBS 看到的是旧画面？**  
A: OBS 浏览器源有独立缓存。右键浏览器源 → 刷新。

**Q: 模拟器连不上 server？**  
A: 确认端口 8765 没被占用。`netstat -ano | findstr 8765`。

**Q: 端口被占用怎么杀？**  
A: `netstat -ano | findstr 8765` 找到 PID → `taskkill /F /PID <pid>`。
