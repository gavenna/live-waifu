# 拆分测试清单

> 验证目的：弹幕工具（danmaku-relay）和直播游戏（war-danmaku）独立运行、通过 :8766 WS 协议正确对接。
>
> 核心理念：弹幕工具广播消息 → 游戏收到消息 → 画面有反应。每一步只验证一个"断裂点是否连通"。

---

## 一、环境准备

```powershell
# 1. 杀掉所有旧进程（避免端口被占）
for ($p = 8765; $p -le 8767; $p++) {
  $line = netstat -ano 2>$null | Select-String ":$p " | Select-String "LISTENING"
  if ($line) {
    $pid = ($line -split '\s+')[-1]
    taskkill /F /PID $pid 2>$null
    Write-Host "已释放端口 $p (PID $pid)"
  }
}
$line = netstat -ano 2>$null | Select-String ":3000 " | Select-String "LISTENING"
if ($line) { $pid = ($line -split '\s+')[-1]; taskkill /F /PID $pid 2>$null }

# 2. 确认端口已清空（应该没有任何输出）
netstat -ano | Select-String ":8765|:8766|:8767|:3000" | Select-String "LISTENING"
```

> 如果上面有输出 → 手动在任务管理器杀残留 process。

```bash

cd D:\Projects\danmaku-relay
```

## 二、弹幕中继独立验证

> 以下全在 **PowerShell** 中执行。弹幕中继只需要 1 个终端窗口。

### 2.1 启动

```powershell
cd D:\Projects\danmaku-relay
node index.js
```

看到 `READY. 弹幕广播 → ws://localhost:8766` 就是启动成功了。

### 2.2 验证

**另开一个 PowerShell 窗口**（这个留着跑 relay，新窗口跑测试命令）：

```powershell
# 确认 API 正常
Invoke-RestMethod http://localhost:8767/api/status
# 预期输出：
# douyin         : False
# bilibili       : False
# subscribers    : 0
```

### 2.3 验证 relay 广播能推送消息

先在**新 PowerShell 窗口**启动一个"订阅者"监听 relay：

```powershell
node -e "const ws=new (require('ws'))('ws://localhost:8766'); ws.on('open',()=>console.log('已连接 relay')); ws.on('message',d=>console.log('收到:',d.toString()))"
```

这会显示"已连接 relay"然后**卡住等待**（正常，它在监听）。

再开**第三个 PowerShell 窗口**，往 relay 发一条测试消息：

```powershell
node -e "const ws=new (require('ws'))('ws://localhost:8766'); ws.on('open',()=>{ws.send(JSON.stringify({type:'danmaku',text:'1',playerId:'test_1',playerName:'测试员'})); ws.close()})"
```

**切回第二个窗口**，应该看到：

```
收到: {"type":"danmaku","text":"1","playerId":"test_1","playerName":"测试员"}
```

看到这个就说明 **relay 广播通道通了** ✅。按 `Ctrl+C` 关掉订阅者和发送窗口。

## 四、模拟弹幕 → 验证画面反应

> 现在有 3 个窗口在跑：窗口1 relay、窗口2 游戏、浏览器。
> **开窗口3（PowerShell）** 来发模拟弹幕。

以下 4 条命令**依次执行**，每条跑完等 2 秒看画面变化：

```powershell
# ① 观众 A 加入红方
node -e "const ws=new (require('ws'))('ws://localhost:8766'); ws.on('open',()=>{ws.send(JSON.stringify({type:'join',team:'red',playerId:'douyin_001',playerName:'红方观众'})); ws.close()})"

# ② 观众 B 加入蓝方
node -e "const ws=new (require('ws'))('ws://localhost:8766'); ws.on('open',()=>{ws.send(JSON.stringify({type:'join',team:'blue',playerId:'douyin_002',playerName:'蓝方观众'})); ws.close()})"

# ③ 红方观众发"杀" → 画面应该出民兵
node -e "const ws=new (require('ws'))('ws://localhost:8766'); ws.on('open',()=>{ws.send(JSON.stringify({type:'danmaku',text:'杀',playerId:'douyin_001',playerName:'红方观众'})); ws.close()})"

# ④ 蓝方老板送龙骑士 → 画面应该出龙骑士（可能有 1 秒预告动画）
node -e "const ws=new (require('ws'))('ws://localhost:8766'); ws.on('open',()=>{ws.send(JSON.stringify({type:'gift',troopKey:'dragonKnight',giftName:'龙骑士',playerId:'douyin_002',playerName:'蓝方老板'})); ws.close()})"
```

**切到游戏画面 tab（:3000）**, 确认：

| 命令 | 画面应该出现 |
|------|-------------|
| ① | 红方队伍显示"红方观众" |
| ② | 蓝方队伍显示"蓝方观众" |
| ③ | 红方民兵从城门走出 |
| ④ | 蓝方龙骑士飞过（或先弹预告文字再出兵） |

> ✅ 4 条全看到 → 弹幕 → relay → 游戏 → 画面 全链路 OK。

## 七、排查速查表

| 症状 | 先看什么 |
|------|---------|
| 端口被占 | `netstat -ano \| Select-String ":8765\|:8766" \| Select-String "LISTENING"` → 拿到 PID → `taskkill /F /PID <pid>` |
| relay 连不上 | relay 窗口有没有 `订阅方接入` 日志？没有 → 游戏侧的 relayClient 重连中，等几秒 |
| 消息发了画面没反应 | 游戏窗口有没有 `[GIFT]` 或 `[ENGINE]` 日志？没有 → relay 没把消息送到游戏 |
| 画面卡住 | 刷新浏览器 tab（Ctrl+F5）；确认不是 COUNTDOWN 阶段（非 PLAYING 不收礼物） |
