## 需求提炼

**来源**：手绘机制图 `09-27-01-游戏机制的思考与复盘.png` 画的是一套「余额驱动」闭环——余额充足→派兵，余额不足→点赞/关注/送礼充值，结束→获胜阵营+贡献榜前3。上一轮核实：闭环里生兵/经济扣款/互动充值/阵营归属/自动续局**已在跑**，真正缺的是收口的三件事（结算露出、关注去重、账目分账）。用户本轮拍板：独立钱包可行、荣誉要、实质奖励也要、但不能破坏平衡、主打「装逼」。

**目标（用户原话拆解）**

| # | 原话 | 落地含义 |
|---|---|---|
| G1 | 「给观众开独立钱包这个可行」 | **分账**：观众的进账/出账落在**观众宿主队**（红=`team 3` / 蓝=`team 4`），AI 主队（`team 1/2`）不再被观众账目扰动 |
| G2 | 「荣誉要有」 | 结算时公布**获胜阵营 + 贡献榜前三**（游戏内文字 + 桌宠 TTS + OBS 叠加三通道） |
| G3 | 「实质性的奖励也要有」 | 前三名获得**可感知、持久、专属**的身份（称号前缀 + 徽章贴图 + 冠名播报 + 榜单高亮） |
| G4 | 「不要破坏游戏平衡…主要装逼」 | 奖励一律**纯展示**：不送兵、不送钱、不解锁强兵种、不给任何战力/资源加成 |
| G5 | （图延续）「余额不足→点赞/关注/送礼」 | 互动是观众钱包的**充值来源**；顺带修「关注重复刷钱」与「点赞连赞被丢弃」 |

**非目标**

- 不扩注入层：不给 `addLabel`/`addAvatar` 加颜色/字号参数、不重打 `game-lib.jar`。装逼只用现有 API 组合（纯文字 + 贴图）。
- 不给任何玩家战力 / 资源加成。
- 不动地图、出生点、AI 难度、收局推手、胜负判定、`RW_ECON_ENABLED` 总开关语义。

**硬约束（改动红线）**

- Debug API **定长参数**：多传一个参数 = 游戏进程 `onGameCrash` 崩溃（历史实测）。所有 `script` 调用逐字保持既有形状，**不新增参数**。
- 播报文本（`debug.showMessage`）**不能含单引号/反斜杠**、换行被压成空格（`announce()` 已净化，新增文案沿用）。
- 可一秒回退：分账走开关 `battleConfig.walletMode`（`viewer` 默认 / `shared` = 旧行为）。
